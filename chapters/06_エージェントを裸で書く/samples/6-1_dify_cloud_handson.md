# 6-1 ハンズオン：Difyクラウド版で質問応答Botを実際に組む

本書 第6章 6-1節「Difyでエージェント型の質問応答Botを組む」を、**Difyのクラウド版（https://cloud.dify.ai）** で実際に確かめるための手順書です。ローカルへのインストール（Docker等）は不要で、ブラウザだけで試せます。

画面ごとの詳細な操作（ナレッジ作成・プラグイン導入・アプリ設定の各画面）は、同じフォルダの [`6-1_dify_agent_setup.md`](6-1_dify_agent_setup.md) にまとまっています。本書はクラウド版固有の部分（アカウント作成・プラン・モデル設定）と、動作確認の観点を補うもので、組み立ての詳細は適宜そちらを参照します。

> **UIについての注意**
> Difyはバージョンアップが速く、メニュー名・画面配置・プラン内容は変わり得ます。本手順の画面名・プランの記述はいずれも**執筆時点**のものです。一致しない場合は公式ドキュメント（https://docs.dify.ai/）と料金ページで現行の内容を確認してください。

## この手順で確かめられること

- 手順（どの道具をどの順で使うか）を一行も書いていないのに、モデルが**結果を見て次の道具を選び直す**こと（本文6-1の「足取り」）
- 知識（ナレッジ）だけで答えられる質問と、知識が空振りしてWikipediaに切り替わる質問の違い
- 実行ログから、エージェントの思考過程とツール呼び出しを後から追えること（本文6-5の観測性への伏線)

## 前提

- ブラウザ（PC推奨）
- Difyクラウド版のアカウント（下記手順で作成。メールアドレス、またはGitHub/Googleアカウント）
- モデル用のAPIキー（Anthropic等）。ただし執筆時点のクラウド版には、お試し用のモデル無料枠が付属する場合があり、その場合はキーなしでも進められます（後述）
- ナレッジに登録するサンプル文書：同じフォルダの [`6-1_サンプル社内規程.md`](6-1_サンプル社内規程.md)（架空の規程）

コードは書きません。Python等の環境も不要です。

## 1. アカウント作成とログイン

1. https://cloud.dify.ai を開きます
2. GitHubアカウント・Googleアカウント、またはメールアドレスでサインアップします
3. ログインすると、ワークスペース（スタジオ）の画面が開きます

本ハンズオンではナレッジ1件・アプリ1件と数往復の動作確認を行います。無料で完了できるかは、残りの利用枠と選択したモデル・埋め込み方式によります。ただし無料プランで作れるアプリ数・登録できるドキュメント数・メッセージ数には上限があり、内容は変わり得るため、公式の料金ページで現行の条件を確認してください。

## 2. モデルプロバイダーを設定する

右上のアカウントアイコン →「設定」→「モデルプロバイダー」を開きます。

- **Anthropicのキーを使う場合**：一覧からAnthropicを選び、APIキーを登録します。一覧に見当たらない場合は、マーケットプレイスからAnthropicのモデルプロバイダー（プラグイン）をインストールしてから登録します（執筆時点のDify 1.x系では、モデルプロバイダーもプラグインとして提供されています）
- **無料枠で試す場合**：執筆時点のクラウド版には、お試し用のモデルメッセージ枠が付属する場合があります。その場合はキー登録なしで、付属モデルを選んでそのまま進められます

どちらの場合も、**ツール呼び出し（Function Calling）に対応したモデル**を使ってください。対応していないモデルだと、この後の「道具を選び直す」動きが観察できません。

> APIキーを登録した場合、Botへの質問文やナレッジの検索結果は、そのモデルの提供元（Anthropic等）のAPIに送信されます。次節の注意（実データを使わない）とあわせて意識しておいてください。

## 3. ナレッジを登録する

`6-1_サンプル社内規程.md` をダウンロード（またはこのリポジトリを clone）して手元に置き、ナレッジとして登録します。

1. 上部メニュー「ナレッジ」→「ナレッジを作成」
2. 「テキストファイルからインポート」で `6-1_サンプル社内規程.md` をアップロード
3. チャンク設定・インデックス方式は**デフォルトのまま**「保存して処理」
4. ステータスが「利用可能」になるまで待ちます（通常1分以内）

画面の詳細は `6-1_dify_agent_setup.md` の「1. ナレッジ（知識）を作る」を参照してください。

> **重要：実在の社内文書をアップロードしないでください**
> クラウド版は社外のサービスです。練習には必ずこの**架空のサンプル規程**を使い、実在の規程・顧客情報・業務データは登録しないでください。会社の生成AI利用ルール上も、この点はサンプル規程の第2章（情報セキュリティ規程）が示すとおりです。

## 4. エージェント型アプリを組む

本文6-1のとおり、アプリの型は**「エージェント」**を選び、モデルに渡すもの4つ（知識・ツール・指示・モデル）を揃えます。

1. マーケットプレイスで **langgenius製の「Wikipedia」プラグイン**をインストールします（`6-1_dify_agent_setup.md` の「2. Wikipediaツールをインストールする」）
2. 「スタジオ」→「最初から作成」→ 型で**「エージェント」**を選択し、名前を付けます（例：社内ドキュメントQA）
3. 「手順」（指示）に次を貼り付けます：

   ```
   あなたは社内の質問に答えるアシスタントです。
   社内ドキュメント（ナレッジ）とWikipediaを参照できます。
   根拠にした情報源がわかるように答えてください。
   ```

4. 「コンテキスト」に手順3で作ったナレッジを追加します
5. 「ツール」にWikipediaを追加します
6. モデル（手順2で設定したもの）を選択します

**指示に「まずナレッジを調べ、なければWikipediaを調べる」といった手順を書かない**のがポイントです（本文6-1）。どの道具をどの順で使うかはモデルに委ねます。設定画面の各項目の詳細は `6-1_dify_agent_setup.md` の「3. エージェント型アプリを作る」を参照してください。

## 5. 動かして観察する

右側の「デバッグとプレビュー」で、次の質問を順に試します。それぞれ「何を確かめる質問か」が違います。

| # | 質問 | 期待される挙動 | 確かめること |
|---|------|--------------|------------|
| 1 | 経費精算の締め切りはいつ？ | ナレッジ検索1回 → 規程を根拠に回答（締め日は毎月末日、申請は翌月第5営業日まで） | 知識で足りるときは1手で終わる |
| 2 | パスワードは何文字以上にする必要がある？ | ナレッジ検索1回 → 「12文字以上」と回答 | 質問1と同じく1手。規程の別の章でも検索が当たる |
| 3 | 社内規程にゼロトラストについての定めはある？なければ、どういう考え方か調べて説明して。 | ナレッジ検索 → 該当なし → **Wikipediaに切り替え** → 「規程に定めはないが、一般には……」とまとめて回答 | 1つ目の道具の**結果を見てから**2つ目を選ぶ足取り（本文6-1の核心） |
| 4 | 出張の日当はいくら？ | ナレッジ検索 → 該当なし → 「規程に定めが見当たらない」旨の回答（Wikipediaを試す場合もある） | 答えがないとき、無理に金額をでっち上げないか |

サンプル規程には「ゼロトラスト」の語も説明も意図的に含めていません（`6-1_サンプル社内規程.md` 末尾の補足参照）。質問3で知識検索が空振りする仕掛けです。

**確認の観点**

- 回答の上部（またはログ）に展開される**思考過程とツール呼び出しの記録**を開き、どの道具が・どんな検索語で・何回呼ばれたかを見る
- 質問1・2と質問3で、ツール呼び出しの**回数と順序**がどう違うかを比べる
- 回答に**引用元（ナレッジの該当箇所）**が示されているかを見る。規程に根拠がある回答と、Wikipedia由来の回答で、出どころの示され方が変わる
- 質問4のように答えが存在しない場合に、断定を避けられているかを見る。もし具体的な金額を答えてきたら、それは根拠のない生成（ハルシネーション）であり、そうした失敗も含めて観察対象
- 左メニュー「ログ」から、過去の実行の足取りを後からたどれることを確認する（本文6-5の観測性に対応）

モデルの応答は毎回同じとは限りません。質問3で一度でWikipediaに切り替わらないこともあります。その場合の調整は次節を参照してください。

## 6. うまくいかないとき

`6-1_dify_agent_setup.md` の「5. うまく動かないとき」の表がそのまま使えます。クラウド版固有の点としては次のとおりです。

| 症状 | 対処 |
|------|------|
| モデル一覧に使いたいモデルが出ない | 「設定」→「モデルプロバイダー」でキー登録済みか確認。プロバイダー自体が無ければマーケットプレイスからインストール |
| 無料枠のメッセージを使い切った | 自分のAPIキー（Anthropic等）を登録して切り替える |
| ナレッジのアップロードや処理が失敗する | 無料プランのドキュメント数・容量上限に達していないか、料金ページで現行の上限を確認 |
| 画面名がこの手順と一致しない | UIは変わり得ます。公式ドキュメントで現行版の名称を確認 |

## 片付け

試し終わったら、作成したアプリとナレッジは削除して構いません。ナレッジを削除すれば、アップロードしたサンプル規程もワークスペースから消えます。
