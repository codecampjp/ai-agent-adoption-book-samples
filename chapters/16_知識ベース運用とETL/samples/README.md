# 第16章 サンプルコード（知識ベース運用とETL ── 再埋め込みコストをオフラインで試算）

本書 第16章は**記述章**（判断軸・比較表・意思決定フロー中心）のため、原則コードは載せていない。
唯一の例外が 16-6「再埋め込みの戦略とコスト試算」で、**全再構築と差分更新のコストの差**を
手元の数字で実感できるよう、そのまま実行できる小サンプルを用意した。
ファイル名の先頭は対応する節番号（`16-6_` = 16-6節）。

ここでは **APIキー・ネットワーク・外部ライブラリ不要のドライラン**で、次を手元で回せる。

1. 「何が変わったか」（文書／埋め込みモデル）から**再埋め込み戦略を選ぶ**（差分／全再構築／使い回す）
2. **全再構築コストと差分更新コストを比較**し、変更率を変えると差がどう開くかを見る（`16-6_reembedding_cost.py`）

## 重要：単価・チャンク数・変更率はすべて「擬似値」

このサンプルの埋め込み単価・チャンク数・変更率は、**構造を見るための擬似値**であり、実額ではない。
本番では次のように置き換える。

- 擬似の**埋め込み単価**（`_common.py` の `EMBED_PRICE_PER_MTOK`） → 使う埋め込みAPIの**実際の料金表**（実額は変動が速いので使う時点の公式で確認）
- 擬似の**チャンク数・トークン**（`Corpus`） → 自社の知識ベースの**実際の総チャンク数・平均トークン**
- 擬似の**変更率**（`change_rate`） → 1回の更新で実際に変わるチャンクの割合（更新日時・ハッシュ・CDCで測る）

構造（コスト＝チャンク数×トークン×単価、モデル変更は全再構築・文書更新は差分、変更率が低いほど差分が安い）は本物に合わせてある。

| ファイル | 対応節 | 内容 | 追加依存 |
|---------|-------|------|---------|
| `_common.py` | 16-6 | 擬似の埋め込み単価・全再構築/差分コスト試算・戦略選択 | なし |
| `16-6_reembedding_cost.py` | 16-6 | 何が変わったか→戦略、全再構築 vs 差分のコスト比較 | なし |

## 動作確認バージョン

- Python 3.10 以上（実行確認は 3.12）。オフラインのドライランは**標準ライブラリのみ**で動く。
- 埋め込み単価・モデル世代は更新が速い。`requirements.txt` に必須の外部依存はなく、
  実際に再埋め込みするときに各埋め込みAPIの公式SDKを追加する。使う時点で公式ドキュメントを確認すること。

## 実行

### セットアップ（オフラインのドライランは依存インストール不要）

```bash
cd samples
python3.12 -m venv .venv          # 3.10+ ならOK
source .venv/bin/activate          # Windows は .venv\Scripts\activate
# オフラインのドライラン（下記）は追加インストール不要（標準ライブラリのみ）
```

### ドライラン（APIキー・ネットワーク・外部ライブラリ不要）

```bash
python 16-6_reembedding_cost.py    # 何が変わったか→戦略、全再構築 vs 差分のコスト比較
```

## 期待される出力（抜粋）

```text
=== 何が変わったか → 戦略 ===
  文書だけ更新          → incremental
  埋め込みモデルを変更    → full_rebuild
  どちらも変わらず       → reuse

=== 全再構築 vs 差分更新（擬似単価）===
  総チャンク: 100,000 / 1チャンク 512 tok
  全再構築コスト（毎回まるごと）: 5.1200（擬似）

  変更率 | 変更チャンク |   全再構築 |   差分更新 |   差分/全再構築
  ------------------------------------------------------------
    0.1% |        100 |    5.1200 |    0.0051 |   0.10%
    1.0% |      1,000 |    5.1200 |    0.0512 |   1.00%
    5.0% |      5,000 |    5.1200 |    0.2560 |   5.00%
   20.0% |     20,000 |    5.1200 |    1.0240 |  20.00%
  100.0% |    100,000 |    5.1200 |    5.1200 | 100.00%
```

変更率が低いほど差分更新は全再構築よりずっと安い（1%なら100分の1）。日常の文書更新は差分で回し、
全再構築は埋め込みモデル乗り換え時に限る。差分を効かせるには「何が変わったか」を知る仕組み
（更新日時・ハッシュ・CDC＝16-4）が要る ── 知識ベース運用の勘どころを手元で試せる。
