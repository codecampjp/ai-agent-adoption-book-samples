# 第15章 サンプルコード（コスト設計とSLA ── 試算をオフラインで回す）

本書 第15章の内容を、そのまま実行できる形にまとめたもの。
ファイル名の先頭は対応する節番号（例 `15-2_` = 15-2節）。

本文では「コストとSLAのトレードオフ地図」（図15-2-1）と試算の構造に集中するため、
掲載コードは骨格に絞っている（本文の掲載コードブロックは0。試算ロジックの実体はここに置いた）。
ここでは **APIキー・ネットワーク・外部ライブラリ不要のドライラン**で、次を手元で回せる。

1. 1リクエストのトークン内訳（入力/出力/ツール往復/判定分）を積み上げ、**月間コストを概算**（`15-2_token_cost.py`）
2. **プロンプトキャッシュのヒット率**を変えると、コストがどう下がるかを**シミュレーション**（`15-4_cache_simulation.py`）
3. **レート制限**にバーストがぶつかったときの**スロットリング**（待って再試行し全体がならされる）挙動（`15-5_throttling.py`）
4. **ROI 試算**（削減工数×人件費 vs 初期構築＋運用コスト）と回収期間（`15-8_roi.py`）

## 重要：単価・レート上限はすべて「擬似値」

このサンプルの単価・割引率・レート上限・トークン数は、**構造を見るための擬似値**であり、実額ではない。
本番では次のように置き換える。

- 擬似の**単価表**（`_common.py` の `PRICING`） → 使うモデル提供者の**実際の料金表**（実額は変動が速いので使う時点の公式で確認）
- 擬似の**トークン数**（`RequestTokens`） → API レスポンスの **`usage`**（`input_tokens` / `output_tokens` / `cache_creation_input_tokens` / `cache_read_input_tokens`）
- 擬似の**レート上限**（`rpm_limit`） → 契約**ティア**の実際の RPM / ITPM / OTPM と `retry-after`
- 擬似の**キャッシュ挙動** → Anthropic の `cache_control` / OpenAI の自動キャッシュ / Gemini のコンテキストキャッシュ

構造（出力＞入力、キャッシュ読み出しは大幅に安い、書き込みは割高、スループットはレート上限で頭打ち等）は本物に合わせてある。

| ファイル | 対応節 | 内容 | 追加依存 |
|---------|-------|------|---------|
| `_common.py` | 15-1〜15-8 | 擬似の単価表・トークン積み上げ・キャッシュ試算・スロットリング・ROI | なし |
| `15-2_token_cost.py` | 15-2 | 1件の内訳→1依頼(×呼び出し回数)→月間の概算 | なし |
| `15-4_cache_simulation.py` | 15-4 | ヒット率を変えたときのコスト削減 | なし |
| `15-5_throttling.py` | 15-5 | レート制限のスロットリング（待って再試行） | なし |
| `15-8_roi.py` | 15-8 | ROI と回収期間（人手コストを数え忘れると見誤る例つき） | なし |

## 動作確認バージョン

- Python 3.10 以上（実行確認は 3.12）。オフラインのドライランは**標準ライブラリのみ**で動く。
- 単価・レート上限・キャッシュ割引・モデル世代は更新が速い。`requirements.txt` に必須の外部依存はなく、
  実料金・実 API に置き換えるときに各社の公式 SDK を追加する。使う時点で公式ドキュメントを確認すること。

## 実行

### セットアップ（オフラインのドライランは依存インストール不要）

```bash
cd samples
python3.12 -m venv .venv          # 3.10+ ならOK
source .venv/bin/activate          # Windows は .venv\Scripts\activate
# オフラインのドライラン（下記）は追加インストール不要（標準ライブラリのみ）
```

### ドライラン（APIキー・ネットワーク・外部ライブラリ不要）

```bash
python 15-2_token_cost.py        # ① 1件→月間のコスト概算
python 15-4_cache_simulation.py  # ② キャッシュのヒット率でコストがどう変わるか
python 15-5_throttling.py        # ③ レート制限のスロットリング挙動
python 15-8_roi.py               # ④ ROI と回収期間
```

## 期待される出力（抜粋）

### `15-4_cache_simulation.py`

```text
=== プロンプトキャッシュ：前置き4,000トークン × 10,000リクエスト（擬似単価）===
  ヒット率 |  キャッシュ無し |  キャッシュ有り |     削減額 | 削減率
  --------------------------------------------------------------
       0% |       40.0000 |       50.0000 |  -10.0000 |  -25%
      70% |       40.0000 |       15.8000 |   24.2000 |   61%
      95% |       40.0000 |        5.9000 |   34.1000 |   85%
```

ヒット率が0%だと書き込み（割高）だけ払ってキャッシュ無しより高くつくが、ヒット率が上がるほど
実効コストが下がる。固定部を前・可変部を後ろに置き、アクセス間隔をTTLに合わせるとヒット率が上がる。
擬似の単価やトークン数を変えると、キャッシュ戦略の損得が手元で見える ── コスト設計の勘どころを試せる。
