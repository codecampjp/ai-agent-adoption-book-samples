# 第17章 知識ベース運用とETL ── サンプルコード

本書第17章は判断軸・比較・意思決定フローが中心の章で、コードを載せているのは 17-6「再埋め込みの戦略とコスト試算」だけです。このフォルダでは、その17-6をAPIキー・ネットワーク・外部ライブラリなしで手元で回せます。確かめられるのは次の2点です。

1. 「何が変わったか」（文書か、埋め込みモデルか）から**再埋め込み戦略を選ぶ**（差分更新／全再構築／使い回す）
2. **全再構築と差分更新のコストを比較**し、変更率が低いほど差分が圧倒的に安いことを数字で見る

## 重要：単価・チャンク数・変更率はすべて「擬似値」

このサンプルの埋め込み単価・チャンク数・変更率は、**構造を見るための擬似値**であり、実額ではありません。擬似単価は、2026年7月31日時点のOpenAIの`text-embedding-3-small`（100万トークン当たり0.02ドル）と`text-embedding-3-large`（同0.13ドル）の価格帯を参考に、同0.10ドルと設定しています。実際の試算では次のように置き換えてください。

- 擬似の**埋め込み単価**（`_common.py` の `EMBED_PRICE_PER_MTOK`）→ 使う埋め込みAPIの実際の料金表（実額は変動が速いので使う時点の公式で確認）
- 擬似の**チャンク数・トークン**（`Corpus`）→ 自社の知識ベースの実際の総チャンク数・平均トークン
- 擬似の**変更率**（`change_rate`）→ 1回の更新で実際に変わるチャンクの割合（更新日時・ハッシュ・CDCで測る）

構造（コスト＝チャンク数×トークン×単価、モデル変更は全再構築、日常的な文書更新は差分を検討、変更率が低いほど差分が安い）は本物に合わせてあります。

## 前提

- Python 3.10 以上（動作確認は 3.12）。すべて標準ライブラリだけで動くため、`pip install` は不要です（`requirements.txt` は本番移行時のメモのみ）。
- 本章のサンプルにAPIキー・外部サービスを使うものはありません。実際に再埋め込みを行う段階で、使う埋め込みAPIの公式SDKを追加します。

## 実行手順

`samples/` ディレクトリ直下で実行します（`_common.py` を読み込むため）。

```bash
cd samples
python 17-6_reembedding_cost.py
```

乱数を使わない決定的な計算なので、出力は毎回同じです。期待される出力は次のとおりです。

```text
=== 何が変わったか → 戦略 ===
  文書だけ更新          → incremental
  埋め込みモデルを変更    → full_rebuild
  どちらも変わらず       → reuse

=== 全再構築 vs 差分更新（擬似単価）===
  総チャンク: 100,000 / 1チャンク 512 tok
  全再構築コスト（毎回まるごと）: 5.1200（擬似）

  変更率 | 変更チャンク |   全再構築 |   差分更新 |   差分/全再構築
  ------------------------------------------------------------
    0.1% |        100 |    5.1200 |    0.0051 |   0.10%
    1.0% |      1,000 |    5.1200 |    0.0512 |   1.00%
    5.0% |      5,000 |    5.1200 |    0.2560 |   5.00%
   20.0% |     20,000 |    5.1200 |    1.0240 |  20.00%
  100.0% |    100,000 |    5.1200 |    5.1200 | 100.00%
```

見どころは2つです。前半の分岐では、埋め込みモデルを変えたときだけ `full_rebuild`（ベクトルに互換性がないため全再構築）になること。後半の表では、変更率1%なら差分更新のコストが全再構築の100分の1で済むこと。差分を効かせるには「何が変わったか」を知る仕組み（更新日時・ハッシュ・CDC＝本文 17-4）が前提になります。

## 自分で確かめる

- **自分の規模で試算する**：`try_reembedding_cost.py`（本リポジトリ限定の追加教材）に、自社の想定値を引数で渡せます。

  ```bash
  python try_reembedding_cost.py --chunks 250000 --tokens-per-chunk 400
  python try_reembedding_cost.py --chunks 100000 --price 0.02 --change-rates 0.005 0.02 0.10
  ```

  `--price` に実際の埋め込み単価（ドル/100万トークン）を入れると、擬似値でなく実額ベースの比較になります。
- **既存スクリプトの定数を書き換える**：`17-6_reembedding_cost.py` の15行目 `Corpus(num_chunks=100_000, tokens_per_chunk=512)` と、37行目の変更率の並び `(0.001, 0.01, 0.05, 0.20, 1.00)` を書き換えても同じことができます。単価そのものは `_common.py` の `EMBED_PRICE_PER_MTOK`（24行目）です。
- **損益分岐を探す**：変更率を上げていくと、差分更新のコストは全再構築に近づきます。自社の更新頻度で「差分の仕組み（変更検知）を作る手間に見合うか」を考える材料になります（PoCでは全再構築も選択肢。本導入時に差分更新への切り替えを見直す——本文 17-6）。

## うまくいかないとき

- `ModuleNotFoundError: No module named '_common'` → `samples/` ディレクトリ直下で実行してください。
- 起動直後に構文エラーになる → Pythonが3.9以前の可能性があります。`python3 --version` で3.10以上を確認してください。
- Windowsで日本語が文字化けする → 環境変数 `PYTHONUTF8=1` を設定して実行してください。
- `ValueError: change_rate は 0.0〜1.0` → 変更率はパーセントではなく割合で渡します（1%なら `0.01`）。
- 試算が実際の請求と合わない → 擬似値のままになっていないか（特に単価）を確認してください。また実際の埋め込みでは、失敗リトライやチャンク分割の変更でトークン数が増えることがあります。
